mtss(docs)

mtss v1.1.1  ·  mc ≥26.2  ·  loader ≥0.19.3  ·  java ≥25  ·  license GPL-3.0  ·  env: client-only

MineTuner Statistics Server (mtss). Client-side Fabric mod, replaces the vanilla F3 screen with a configurable stat HUD. This site is the implementation reference, not the user manual — for install/usage instructions read the README. Everything here assumes you've read the source or are about to.

No search box. Use ctrl+F. No dark mode toggle, your browser has one. This is one CSS file, zero JS, zero build step — docs/ is served as-is by GitHub Pages.

tl;dr package map

bottled.mtss ├── MtssMod common entrypoint (logger only, server env is a no-op) ├── MtssClient client entrypoint — keybinds, HUD attach, command reg, tick hook ├── MtssDataHolder static bag of latest sampled values, written by StatSource impls ├── sample/ StatSource, Cadence, SamplingDriver, SourceRegistry, HardwareSensorPoller │ └── sources/ 11 StatSource impls, grouped by what they read (perf/player/world/...) ├── stat/ StatDefinition interface + StatRegistry (token/key lookup) │ └── stats/ 46 StatDefinition impls, one file per stat ├── hud/ render pipeline: MtssRenderer, LineBuilder, LineCache, GraphRenderer, │ TemplateEngine, ColorMath, HudMotion, ListPositioner ├── gui/ custom drag/drop editor (MtssGuiScreen) + panel/ subpackage ├── config/ MtssConfig (persisted model, atomic save/load) + config/cloth/ (Cloth Config screen) ├── command/ MtssCommand — /mtss gui, /mtss config └── mixin/ ClientPacketListenerMixin (TickingState → tick rate)

see architecture.html for the actual dataflow between these.
